# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A single-page PWA (Spanish UI) that tracks office visits against a monthly quota, with automatic Colombian holidays, two-way sync to a dedicated Google Calendar, an append-only audit log in a Google Sheet, and optional real-time sync between devices through Firebase (Firestore). Deployed as static files on GitHub Pages; installed on Android via Chrome "Add to home screen". `README.md` is the spec (in Spanish): business rules RN-01…RN-30 with code locations, Mermaid diagrams, what each repo file and external service (GitHub, Google Cloud, Firebase) is for and `docs/FIREBASE.md` the step-by-step Firebase guide (phases A–C; A is implemented) — keep both in sync when behavior changes.

## Development

- No build step and no runtime dependencies. `index.html` holds only markup and one `<script type="module" src="js/app.js">`; styles are in `css/styles.css`; logic is 34 ES modules in `js/` using a light hexagonal architecture (README §4): `nucleo/` pure business rules (no DOM/network/storage/clock — enforced by a test), `estado/` (`S`, `now`, save/load), `adaptadores/` (Google, Firestore, crypto, error reporting; no business rules), `funcionalidades/{mes,marcar-dia,avisos,historial,conexion,sincronizacion}` (execute core decisions + render their UI), `ui/` (`render()`, icons, motion/sheets). Layers only depend inward. Only `app.js` runs code at load; other modules export `iniciar…()` functions called from `app.js` in a fixed order (timer order matters). A new `js/` file must be added to the `JS` list in `sw.js`.
- **Tests** (`tests/`, Node ≥ 22, `cd tests && npm install && npm test`; jsdom is the only dev dependency): `equivalencia.test.mjs` runs every scenario (`escenarios.mjs`, plus seeded random ones) against the frozen v15 copy in `tests/referencia-v15/` and the current code with identical fake clock/Google/GIS/Firebase (`tests/entorno/`) and asserts identical snapshots (S, localStorage, card HTML, every Google request in order, Firestore writes, dialogs); `reglas.test.mjs` asserts RN-01…RN-30 with hand-written expectations; `paridad.test.mjs` compares core functions against v15 over thousands of inputs; `robustez.test.mjs` covers error handling; `estructura.test.mjs` enforces the architecture, the `sw.js` list, version parity and no empty `catch`. Run them before publishing. An intentional behavior change will make the matching equivalence scenario fail — confirm it's the expected diff and update `reglas.test.mjs`; never edit `tests/referencia-v15/`.
- Errors: never swallow. Use `reportar(where, err)` / `seguro(where, fn)` from `js/adaptadores/errores.js`; uncaught errors are captured globally (`officeTrackerErrores()` in the console). `load()` validates stored data (keeps a copy of unreadable data in `ot-data-v2-danado`), Firestore input is validated, `applyChange()` rejects invalid keys/types, and each card renders isolated so one failure doesn't blank the screen.
- Run locally with any static server from the repo root (e.g. `python -m http.server 8000`; ES modules don't load from `file://`). Google sign-in only works from origins registered as "Authorized JavaScript origins" on the user's OAuth Client ID, so add `http://localhost:8000` there to test Calendar sync locally. Firebase sign-in also needs `localhost` in Authentication → Authorized domains (there by default).
- **When publishing changes, bump `VERSION` in `sw.js` and `APP_VER` in `js/nucleo/constantes.js` together** (`'v16'` → `'v17'`…; a test checks they match). `APP_VER` is shown in the header/footer and written to the log. The SW fetches HTML, JS and CSS network-first with `cache:'no-cache'` (GitHub Pages sends `max-age=600`); icons/manifest are cache-first; Google origins and non-GET requests bypass the SW entirely.
- Code style in `js/` and `css/` is dense, compact one-liners with Spanish comments and `═══` section banners; match it.
- `graphify-out/` holds the knowledge graph of the app; `.graphifyignore` keeps `.claude/` skills out of it.

## Architecture (where things live: README §4.2; function names below are unchanged from the pre-module version)

**State**: one global object `S` holds everything — `data` (`{ 'YYYY-MM-DD': 'office'|'vacation' }`), `evIds` (day → Calendar event id), `pending` (days not yet pushed to Calendar), `log` (audit trail), `logOut`/`hidden`/`hideOut` (log entries deleted in the app), `rem`/`nonces`/`skip` (reminder events), `fs` (Firestore day state with timestamps), `sheetId`, `account`, `legacy` (v2 events to clean up), plus token/calendar ids. `save()`/`load()` persist to `localStorage` key `ot-data-v2` with schema `v:3`; `load()` migrates older shapes by marking all days pending and moving old event ids to `legacy`. Dates are always local-time `YYYY-MM-DD` keys via `toKey`/`fromKey`.

**Quota logic** (`calcularMes(data,year,month,now)` in `nucleo/meta.js`, message choice in `estadoMes()`): base 8 visits/month; each week containing a holiday or vacation has quota 1 instead of 2, so target = `8 − adjusted weeks`. Weeks straddling months are displayed whole but only days inside the visible month count. Holidays are computed per year (`holidays(y)`, memoized in `_HC`) from fixed dates, Ley Emiliani (moved to Monday), and Easter-relative dates. It also returns `open` (free weekdays left from today: no holiday, not marked), `slack = open − remaining` and `must` (all `open` days when `slack <= 0`). `must` drives the hero alert ("Tienes que ir sí o sí" / "No alcanzas"), the dashed `.must` day cells, and `tituloAviso()` (the 10:00 reminder becomes "⚠️ Hoy tienes que ir a la oficina"; existing reminders are PATCHed when the title changes, tracked via `S.rem[k].t`).

**Change flow**: `toggle()` (next state from `siguienteEstado()`) → `applyChange(key,next,src)` updates `S.data`, appends to `log` (`logChange()`), writes Firestore (`fsDay()`, when signed in), marks `pending`, re-renders, and calls `schedulePush()` which waits `UNDO_MS` (5s) for the undo toast, then pushes the day to Calendar and the log to the sheet. `flushPushes()` pushes immediately when the page is hidden. `pushDay()` skips days still in the undo window (`timers[key]`).

**Sync queue and indicator**: all Google API work goes through `gcal()` (accepts a Calendar path or a full https URL for Sheets/Drive; maps Google errors to readable messages, e.g. API not enabled or missing scopes) and is serialized through `enqueue()` (a single promise chain) — keep new API work inside `enqueue`. `enqueue()` counts jobs in `S.busy`; `step()` sets the sync-step label shown in the Google card; `#topbar` animates while `isBusy()`; `S.lastSync` feeds "Al día · HH:MM".

**Calendar sync**: OAuth via Google Identity Services token client (scopes `calendar.app.created` — only calendars this app creates — plus `calendar.calendarlist.readonly`, required because `calendarList.list` rejects app.created alone, plus `drive.file` for the history spreadsheet; `calendar.events` is requested solely for `cleanupLegacy()`). The callback rejects partial grants (`hasGrantedAllScopes`). `ensureCalendar()` lists calendars on every sync and keeps exactly one "Office Tracker" per account: lowest id wins, `mergeCalendar()` copies day events from duplicates and deletes them; it never creates a calendar if the lookup failed. `syncAll()` = `ensureCalendar()` → `pullSheet()` (only without Firebase) → `reconcileMonth()` or `reconcileMonthFS()` → `reconcileReminders()` → `syncSheet()` → `pushHidden()`. Who-wins decisions are pure functions in `nucleo/conflictos.js` (`importarDeCalendar`, `decidirDiaConFirebase`, `decidirDiaRemoto`, `elegirEvento`, `explained`), evaluated per day with live state inside the executors in `funcionalidades/sincronizacion/`. `reconcileMonth()` (no Firebase): pending local changes win, otherwise Calendar wins; duplicate same-day events are deleted; `classify()` maps event titles with 🏢/oficina vs 🏖️/libre/vacaciones. `explained()` stops it from logging a duplicate `calendar` entry when the latest log entry for that day already accounts for the change.

**Change detection**: `checkChanges()` runs every 10 s while visible and only triggers `syncAll()` when Calendar has events with `updated` > `calCursor` (`updatedMin` + `showDeleted`) or the sheet's Drive `modifiedTime` changed. With Firebase signed in it runs every 60 s and checks Calendar only (Firestore already delivers cross-device changes). A full sync also runs every 5 min, on `online`, on window `focus` and on `visibilitychange` to visible.

**Firebase (real-time, optional)**: compat SDK 10.14.1 loaded with `defer`; `iniciarTiempoReal()` on DOMContentLoaded (the app works without it). `FB_CONFIG` is the public web config of project `office-tracker-510522`. When signed in (`fbOn()`), Firestore `users/{uid}/days|log|hidden` is the source of truth: `applyChange`/`doUndo` call `fsDay()`, `logChange` calls `fsLog()`, `deleteLog` calls `fsHide()`. `onSnapshot` listeners (`onFsDays`/`onFsLog`/`onFsHidden`, with `includeMetadataChanges` and `firstFromServer()` so the one-time migration of local data waits for the server, not the empty cache) apply remote changes. Day docs are never deleted (`type:null` tombstone; newest `ts` wins; a local change in the undo window or newer than the doc is rewritten). `reconcileMonthFS()` treats Calendar as a mirror: an event is imported only when its `updated` is newer than the Firestore `ts` (or a known event vanished and Firestore hasn't changed since the last sync); otherwise the day is marked pending and Calendar is corrected.

**History spreadsheet**: `syncSheet()` appends every `S.log` entry without `up:true` as an audit-log row (`LOG_COLS`/`logRow()`: ISO timestamp, action, origin, states, device, account, app version… and column W with the entry as JSON) to the Google Sheet "Office Tracker · Historial" (found by name via Drive `files.list`, created by `ensureSheet()` inside the app-created folder `office-tracker` in My Drive root). `setupSheet()` runs once per session and repairs the `Historial` and `Ocultos` tabs, header, frozen row and filter. The sheet is append-only: `deleteLog()` removes entries from the app only, parks not-yet-uploaded ones in `S.logOut` so they still reach the sheet, and shares the deletion through the `Ocultos` tab (`pushHidden()`) and Firestore `hidden`. Without Firebase the sheet is also the shared history: `pullSheet()` reads new Historial rows (`sheetRead` tracks rows already read this session; `parseRow()` falls back to the readable columns for rows without JSON) and merges them into `S.log` by id.

**Reminders**: for weekdays that aren't holidays/marked/skipped within `HORIZON` (21) days, two timed events (`SLOTS`: 10:00 and 16:30, `America/Bogota`) are created, each with a random nonce and a deep link `?d=DATE&r=SLOT&n=NONCE`. Marking a day deletes its remaining reminders. Day vs reminder events are distinguished by `extendedProperties.private.kind` (`day`/`reminder`) and tagged with `appId`.

**Deep links**: `readDeepLink()` parses and strips the query string; `openNotifSheet()` verifies the nonce (`verifyNonce` → `ok`/`bad`/`unknown`, shown as Aviso ✓/⚠/?) and offers "Fui a la oficina / Día libre / Hoy no fui". Audit log entries record source (`manual`, `notif`, `calendar`, `undo`), timestamp, change id and device id (`S.dev`), and the last 10 entries per day are written into the Calendar event description by `dayBody()`.

**Rendering**: `render()` rebuilds the whole UI from `S` via template strings into `innerHTML`; there's no framework or virtual DOM. Long-press a day → `openDaySheet()` history (with per-entry delete and a link to the sheet). Styling is class-based with CSS custom properties in `:root` (dark theme, Geist font, Scotia red `--brand`); day/state colors come from classes like `.s-office`, `.hol`, `.today`, `.must`, not inline styles. UI icons are inline SVGs in `IC` with labels in `TYPE_UI`; **don't change `TYPE_LBL`** — its emoji become Calendar event titles that `classify()` parses back. Sheets/modals are bottom sheets opened/closed through `showOv()`/`hideOv()` (WAAPI exit animation, then `style.display='none'`; `dataset.closing` marks one mid-exit). Motion lives in `ui/movimiento.js`: `afterRender()` (segment fill, number swap, goal celebration), `popDay()`, `slideMonth()`, all via `anim()` which no-ops under `prefers-reduced-motion`. Animate only `transform`/`opacity`. Hover styles stay inside `@media (hover:hover) and (pointer:fine)`.
